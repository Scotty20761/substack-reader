Key points
  • TAM ของ CPU ถูกปรับขึ้นสามครั้งในเก้าเดือน ตอนนี้เกิน $200B ภายในปี 2030 (CAGR ราว 50%)
  • Helios เริ่มส่งมอบเชิงการผลิตเดือนกันยายน ระบบชุดแรกรันที่ OpenAI, Meta, Microsoft และ Oracle
  • Helion รองรับสูงสุด 32,768 CPU core; Verano ผลิตปี 2027 เน้นพลังงานต่ำและหน่วยความจำ

ผู้พูด: Lisa Su ประธานและซีอีโอ AMD

สรุป: ข้ออ้างที่มีนัยสำคัญที่สุดของ AMD คือ ประมาณการ TAM ของ CPU ถูกปรับขึ้นถึงสามครั้งในเก้าเดือน และตอนนี้เกิน $200B ภายในปี 2030 อีกข้อคือ Helios เริ่มส่งมอบเชิงการผลิตตั้งแต่เดือนกันยายน แร็ก Helion ตัวใหม่เปลี่ยนแนวคิด CPU สำหรับเอเจนต์ให้กลายเป็นผลิตภัณฑ์จริง ส่วน Verano ขยายโรดแมป CPU ไปสู่คอนฟิกที่ใช้พลังงานต่ำลงและเน้นหน่วยความจำมากขึ้น

1. ตลาด CPU กำลังถูกนิยามใหม่ด้วยการประมวลผลของเอเจนต์ ไม่ใช่แค่การเป็นโฮสต์ให้ GPU

Su ประเมินโอกาสของตัวเร่ง AI ในดาตาเซ็นเตอร์ไว้ที่ราว $1.5T ภายในปี 2030 แต่การเปลี่ยนแปลงที่คมกว่าอยู่ที่ CPU: ตอนนี้ AMD มองว่าตลาดเกิน $200B ภายในปี 2030 โต CAGR ราว 50% ตลอดหลายปีข้างหน้า ตัวเลขเหล่านี้เป็นการคาดการณ์ตลาดของ AMD เอง ไม่ใช่ประมาณการของวอลล์สตรีท

ตรรกะเบื้องหลังคือ เอเจนต์สร้างงานจำนวนมากนอกเหนือจากการอนุมานของโมเดล ไม่ว่าจะเป็นการรันโค้ด การเรียกใช้แอปพลิเคชัน การจัดการบริบท และการประสานงานเอเจนต์ตัวอื่น ซึ่งเพิ่มภาระงาน CPU ควบคู่ไปกับโปรเซสเซอร์ที่ทำหน้าที่รองรับ GPU อยู่แล้ว ส่วนการระบุขนาดตลาดแบบเก่าราว ~$20B ในคีย์โน้ตไม่ควรใช้เป็นจุดเริ่มต้นที่เทียบกับ CAGR ใหม่ได้โดยตรง

2. Helios เดินจากการเปิดตัวสู่การติดตั้งให้ลูกค้ารายแรก

Su บอกว่าการส่งมอบเชิงการผลิตเริ่มในเดือนกันยายน และการเร่งกำลังผลิตจะต่อเนื่องตลอด Q4 และครึ่งแรกของปี 2027 AMD ระบุว่าระบบชุดแรกติดตั้งและทำงานอยู่แล้วที่ OpenAI, Meta, Microsoft และ Oracle โดยการส่งมอบ การติดตั้ง และการตรวจสอบ workload กำลังดำเนินอยู่

นี่เป็นหมุดหมายด้านการลงมือทำที่มีความหมาย แต่การติดตั้งชุดแรกยังไม่เท่ากับการทำตามพันธะหลายกิกะวัตต์ที่ประกาศไว้ก่อนหน้านี้ให้ครบ คำถามต่อไปคือจังหวะที่การติดตั้งเหล่านี้จะแปรเป็นการ deploy ขนาดใหญ่ที่ทำซ้ำได้

3. Helion เล็งไปที่ workload ที่ต่างจาก Helios

Helion ออกแบบรอบการประมวลผลของเอเจนต์ มีคอนฟิกที่เน้น CPU สำหรับไฮเปอร์สเกลเลอร์ และคอนฟิก CPU/GPU แบบรวมสำหรับองค์กร สเปกที่ AMD เผยแพร่รองรับ CPU core สูงสุด 32,768 core ขณะที่ตัวกำหนดเส้นทางโมเดลในตัวจะส่งคำขอไปยังโมเดลและทรัพยากรประมวลผลที่เหมาะสม

ความแตกต่างนี้ตั้งใจทำ: ไฮเปอร์สเกลเลอร์อาจแยกแร็กอนุมานกับแร็กประมวลผลเอเจนต์ ส่วนองค์กรที่รันโมเดลขนาดเล็กในสถานที่ของตัวเองอาจอยากได้สองหน้าที่ในที่เดียวกัน คอนฟิกสำหรับพันธมิตรวางแผนไว้เดือนพฤศจิกายน 2026 นี่คือสถาปัตยกรรมการ deploy แบบที่สอง ไม่ใช่แค่ Helios ตัวเล็กลง

4. Verano ทำให้หน่วยความจำและพลังงานของระบบกลายเป็นส่วนหนึ่งของการถกเรื่อง CPU

AMD โชว์ Verano ซึ่งเป็น EPYC ตระกูล Venice ที่ปรับให้ใช้พลังงานระบบต่ำลง ใช้แนวทางหน่วยความจำแบบ LPDDR และอัปเดตการเชื่อมต่อ CPU-ไป-GPU วางแผนผลิตในปี 2027

ประเด็นสำคัญคือ AMD ไม่ได้มอง workload CPU ที่เกี่ยวกับเอเจนต์ทุกอย่างเป็นการแข่งขันเรื่องจำนวน core สูงสุด โปรเซสเซอร์โฮสต์ การประมวลผลเอเจนต์แบบหนาแน่น และเอเจนต์ที่ต้องการเทคนิคสูง ต้องการสมดุลที่ต่างกันระหว่างแบนด์วิดท์หน่วยความจำ การเชื่อมต่อ ประสิทธิภาพต่อ core และพลังงาน

5. เศรษฐศาสตร์ของแร็กขึ้นอยู่กับระบบรอบข้าง

AMD อ้างว่า Helios ได้เปรียบ 30% ด้าน token ต่อดอลลาร์ แต่คีย์โน้ตไม่ได้ให้รายละเอียดการเปรียบเทียบมากพอที่จะขยายความได้เปรียบนี้ไปยัง workload อื่น ข้อโต้แย้งเชิงวิศวกรรมที่กว้างกว่าของ AMD ทนทานกว่า คือ พลังประมวลผล ความจุหน่วยความจำ แบนด์วิดท์หน่วยความจำ เครือข่าย และซอฟต์แวร์ ต้องพัฒนาไปพร้อมกัน

นัยเชิงการลงทุนมีสองชั้น: AMD กำลังเข้าหาโอกาส CPU ที่ใหญ่ขึ้น พร้อมกับขยับข้อเสนอด้าน GPU ไปสู่ระบบสมบูรณ์ที่ deploy ได้ แต่ทั้งการคาดการณ์ TAM และเบนช์มาร์กของผู้ขายก็ยังไม่ได้ยืนยันส่วนแบ่งรายได้หรือส่วนร่วมของมาร์จิ้นในที่สุด

ผู้พูด: Ian Buck รองประธาน Hyperscale & High-Performance Computing, NVIDIA

สรุป: NVIDIA รวมการ deploy Vera Rubin ปัจจุบันเข้ากับตัวอย่างล่วงหน้าของโดเมน NVLink แบบ Rubin Ultra ขนาด 576 GPU ที่ใช้ co-packaged optics สิ่งที่สำคัญไม่แพ้กันคือแร็ก Vera CPU โดยเฉพาะสำหรับประมวลผลเอเจนต์ ควบคู่กับงานซอฟต์แวร์และการจัดการพลังงานที่มุ่งเพิ่มพลังประมวลผลที่ใช้ได้จริงภายในสิ่งปลูกสร้างที่มีข้อจำกัด

1. แยกการ deploy Vera Rubin ออกจากตัวอย่างล่วงหน้าของ Rubin Ultra

Buck อธิบายว่า Vera Rubin อยู่ในการผลิตและเข้าถึงดาตาเซ็นเตอร์ของลูกค้าแล้ว ส่วนตัวอย่างล่วงหน้าของ Rubin Ultra เป็นหมุดหมายคนละเรื่อง: ระบบเชื่อมต่อ NVLink 576 GPU ที่วางแผนไว้ ครอบคลุมหลายแร็ก ใช้ถาดสวิตช์ co-packaged optics รุ่นถัดไป

ข้อสรุปคือ NVIDIA ตั้งใจขยายโดเมนตัวเร่งที่เชื่อมแน่นให้เกินแร็กที่ใช้ทองแดงในปัจจุบัน ตัวอย่างล่วงหน้านี้สนับสนุนโอกาสด้านเนื้อหาออปติกในอนาคต แต่ไม่ควรนับเป็นคอนฟิก 576 GPU ที่กำลังส่งมอบอยู่

2. แร็ก Vera CPU ไม่ใช่แค่อุปกรณ์เสริมของ GPU

Buck อธิบายแร็กเฉพาะที่มี Vera CPU 256 ตัวสำหรับประมวลผลเอเจนต์และงานที่เกี่ยวข้อง สถาปัตยกรรมของ NVIDIA แยกบทบาทนี้ออกจากระบบเทรน/อนุมาน Vera Rubin NVL72: แร็ก CPU รองรับการเรียกใช้เครื่องมือ การประสานงาน และการรันแบบ sandbox

แนวทางสถาปัตยกรรมเน้นประสิทธิภาพต่อ core ที่คงที่และแข็งแรง การเข้าถึงหน่วยความจำ และ throughput ที่คาดเดาได้ แทนที่จะปรับเพื่อต้นทุนต่อ core ต่ำสุดเพียงอย่างเดียว ซึ่งเปิดอีกเส้นทางให้ NVIDIA เข้าถึงการใช้จ่ายของดาตาเซ็นเตอร์ รวมถึงงานที่ไม่ได้รันบน GPU ของตัวเองโดยตรง

3. Co-packaged optics เริ่มที่ scale-out ก่อน แล้วจึงโดเมน scale-up ที่ใหญ่ขึ้น

Spectrum-X Photonics ถูกนำเสนอเป็นผลิตภัณฑ์ scale-out ที่ส่งมอบในปีนี้ ส่วน NVLink แบบออปติกผูกกับโรดแมป scale-up รุ่นถัดไป ทั้งสองเป็นตลาดและกำหนดการนำไปใช้ที่ต่างกัน

Buck ยังเน้นเครือข่ายหลายระนาบ (multiplane) และการตรวจจับความล้มเหลวระดับฮาร์ดแวร์อย่างรวดเร็ว เป้าหมายทางเศรษฐกิจไม่ใช่แค่แบนด์วิดท์ที่สูงขึ้น แต่คือการหลีกเลี่ยงสถานการณ์ที่ลิงก์เสียตัวเดียวทำให้ตัวเร่งราคาแพงจำนวนมากช้าลงหรือหยุดชะงัก ส่วนการปรับปรุงด้านประสิทธิภาพพลังงานและจำนวนสวิตช์ที่เขาพูดถึงเป็นข้ออ้างของผู้ขาย ผูกกับการเปรียบเทียบสถาปัตยกรรมเฉพาะแบบ

4. การจัดการพลังงานปลดล็อกกำลังประมวลผลได้โดยไม่ต้องต่อไฟจากสาธารณูปโภคใหม่

การพูดถึง MaxLPS ของ NVIDIA เน้นที่ช่องว่างระหว่างพลังงานตามป้ายกับการใช้จริงของ workload ถ้าซอฟต์แวร์เฝ้าดูความต้องการอย่างต่อเนื่องและบังคับขีดจำกัดทางไฟฟ้า ผู้ดำเนินการก็อาจติดตั้งหรือใช้พลังประมวลผลได้มากขึ้นภายใต้กรอบพลังงานที่จัดสรรไว้เท่าเดิม

นี่คือโอกาสด้านการใช้ประโยชน์ ไม่ใช่การสร้างไฟฟ้าเพิ่ม ปริมาณที่เรียกคืนได้ขึ้นกับความหลากหลายของ workload ความระมัดระวังของการจัดสรรเดิม และความไวของระบบควบคุม ตัวอย่างในทรานสคริปต์มีตัวเลขที่ไม่สอดคล้องกัน ดังนั้นกลไกน่าเชื่อถือกว่าตัวเลขการเพิ่มระดับทั้งฟลีตที่แม่นยำ

5. การผลิตและการ deploy กำลังกลายเป็นส่วนหนึ่งของความแตกต่างของแพลตฟอร์ม

Buck เทียบการประกอบถาดประมวลผลรุ่นก่อนที่ใช้ราว 90 นาที กับถาดดีไซน์ไร้สายเคเบิลรุ่นใหม่ที่ใช้ประมาณหนึ่งนาที การเปรียบเทียบนี้เป็นของถาดประมวลผล ไม่ใช่แร็กที่สร้างเสร็จทั้งหมดหรือคลัสเตอร์ที่เปิดใช้งานแล้ว

ผลงานด้าน MGX ที่กว้างกว่านั้นทำให้อินเทอร์เฟซของแร็ก ระบายความร้อน พลังงาน และการซ่อมบำรุงเป็นมาตรฐาน NVIDIA พยายามทำให้การผลิต การติดตั้ง และการซ่อมบำรุงทำซ้ำได้ข้ามพันธมิตร ขณะที่ยังรักษาความได้เปรียบของการออกแบบร่วมระดับระบบ การพูดถึง 800V ขยายความพยายามนี้เข้าไปถึงสิ่งอำนวยความสะดวก แทนที่จะสมมติว่าดาตาเซ็นเตอร์เดิมทุกแห่งรับแร็กรุ่นถัดไปได้โดยไม่ต้องแก้ไข
